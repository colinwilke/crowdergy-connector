# v3.37.0 — Slimmer Home Assistant entities (per-device sensor mirror removed)

No breaking changes for control/telemetry, no HA-version bump, no new
entity/preset schema slots → no new Box-vendor matrix row. After updating,
re-provision (or restart) so the old duplicate sensors disappear.

## Changed

- **Removed the per-device `sensor` mirror platform** (`sensor.py`). The
  connector no longer creates `Crowdergy_Current Power` and
  `Crowdergy_State of Charge` sensors for each device. Those only duplicated
  the user's existing real integration entities — their values came from
  `coordinator.data`, which is read from exactly those entities — so HA
  device/entity lists showed e.g. "Solar Power" twice, distinguishable only
  by the `Crowdergy_` prefix.

## Kept

- **Per-device `switch` "Crowdergy AI"** — a real control surface mirroring
  the per-device Crowdergize consent flag (POSTs `toggle_active`, kept in
  sync with the iOS toggle via the backend).
- **Integration-wide `binary_sensor.crowdergy_connected`** — SSE liveness so
  you can write take-over automations when Crowdergy goes offline.

## Why

The two mirror sensors were pure duplication and made the HA entity list
confusing next to the user's original integration entities. Nothing reads or
switches through these generated platform entities — telemetry and dispatch
always go through the mapped real entities — so removing them has no effect
on control or data.

## Notes for existing installs

No schema/backend/preset change. After updating the connector, re-provision
the box (or restart Home Assistant) so the stale `sensor.crowdergy_*`
entities are cleared. The "Crowdergy AI" switch and `crowdergy_connected`
binary sensor are unaffected.
