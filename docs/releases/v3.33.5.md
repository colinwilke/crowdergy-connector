## v3.33.5 — Remove API-URL from the setup flow (#22)

User-facing config-flow change. Existing installs keep working and do **not**
need re-provisioning — the API URL was only ever an optional override.

### Changed

- **API-URL field removed from the interactive setup flow.** The first
  onboarding step (`user`) now only asks for the pairing code; the connector
  always pairs against the default Crowdergy backend. The internal
  `api_url` value is still stored on the config entry, so the coordinator,
  reauth and token refresh are unchanged.
- **Shortened the onboarding step text** (German + English).

Self-hosted / dev backends remain configurable through the headless box
provisioning service (`provision_box`), which still accepts an optional
`api_url`.

No HA-version bump, no entity/preset changes → no new Box-vendor matrix row.
