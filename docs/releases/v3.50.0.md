# v3.50.0 — optional ECO setpoint for heating and warm water

Some heat pumps run a time program and hold either the comfort or the ECO
setpoint, depending on the time window, and ignore the other one. If the
integration only writes the comfort setpoint, a command can then have no
effect at all.

## New: "Eco-Sollwert (optional)"

Heating and warm-water devices get an optional second control entity in the
device settings (number, input_number, climate or water_heater). When it is
mapped, every target temperature the integration writes to the main control
entity — the "on" and "off" values — is also written there.

- Applies to every write path: live commands, resync, self-heal, the
  handover when Crowdergy AI is switched off, and the repeat ("hold") loop.
- The ECO entity has its own checks: the value is clamped to that entity's
  limits (logged as a warning), compared against the clamped value, guarded
  by its own write limit, and only written when it differs — also in
  "repeat command" mode.
- Control consent applies as everywhere else.
- In automatic hold mode, if someone else changes the ECO setpoint, this
  counts as a manual override: the device pauses for two hours, as with the
  main setpoint. Drift right after the integration's own write is simply
  repaired.
- Switches and mode values are never mirrored; reading the device state
  stays on the main entity.

## Upgrading

No backend change needed. No entry-data change, no re-provisioning. Nothing
changes until the new field is mapped in the device settings.
