# v3.38.0 — One "Crowdergy" hub device in Home Assistant

No breaking changes for control/telemetry, no HA-version bump, no new
entity/preset schema slots → no new Box-vendor matrix row. After updating,
re-provision (or restart HA) so the old per-device cards disappear.

## Changed

- **The connector now registers a single integration-wide "Crowdergy"
  device** instead of one `Crowdergy_<Name>` device per mapped device. All
  per-device "Crowdergy AI" switches and the `crowdergy_connected`
  connectivity sensor attach to it.
- Previously each mapped device got its own `Crowdergy_<Name>` device — a
  duplicate card next to the user's real integration device, and (after the
  v3.37.0 sensor-mirror removal) an empty card for read-only types
  (solar/grid) that never get a switch.
- **Switch naming:** because the switches now share one hub device, each
  carries the device name in its own friendly name — "Crowdergy AI:
  <device>". Entity IDs (`crowdergy_<slug>_ai`) are unchanged.

## Why

The per-device Crowdergy devices cluttered Home Assistant's device list —
duplicates next to the user's real devices, plus empty cards for solar/grid.
Grouping the switches and the connectivity sensor under one "Crowdergy" hub
keeps the device list clean while preserving every per-device switch.

## Notes for existing installs

No schema/backend/preset change. After updating the connector, re-provision
the box (or restart Home Assistant) so the stale `Crowdergy_<Name>` devices
(now entity-less) are cleared. The "Crowdergy AI" switches and the
`crowdergy_connected` binary sensor keep working, now grouped under the
"Crowdergy" device.
