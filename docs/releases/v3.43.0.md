# v3.43.0 — device profiles resolve independently of your device names

Entity ids embed the device name you chose during integration setup
(`sensor.solar_battery_power` vs `sensor.wechselrichter_battery_power`),
so a shared device profile ("Geräteprofil") could only be re-applied on
another installation via a suffix heuristic — and the profile picker
pre-filled the contributor's raw entity ids verbatim, which usually don't
exist on your system.

With this release profiles resolve **by registry identity**, fully
independent of any user-chosen naming.

## Added

- **Identity capture on contribute.** A shared profile now also carries
  `entity_identity_map`: per entity slot the HA registry identity
  (`platform` + `translation_key`/`original_name`) — stable across
  device renames AND entity renames. Privacy rule: the `unique_id` is
  deliberately never transmitted (it often embeds device serial
  numbers); the backend hard-rejects it.
- **Identity resolution on apply.** Picking a profile now resolves each
  entity slot against YOUR installation before pre-filling the entity
  step: exact id → registry identity → suffix match. Only an
  unambiguous hit replaces the pre-fill; ambiguous (true multi-inverter)
  or unresolvable slots keep the contributor's id verbatim so you pick
  yourself — the resolver never guesses.

## Notes

- Existing profiles without the identity data keep working unchanged via
  the suffix match; they gain identities the next time someone
  contributes them.
- Requires no re-provisioning; fully backward compatible with older
  backends (the field is simply absent → suffix resolution).
- The Crowdergy Box applies the same identity ladder in its setup wizard
  (separate release channel).
