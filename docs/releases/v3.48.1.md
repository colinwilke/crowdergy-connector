# v3.48.1 — a broken example in the new field's help text

v3.48.0 added the optional *setpoint the device actually runs* mapping. Its
help text offered an example written as `sensor.<hp>_target_temperature_water`,
with the device-name placeholder in angle brackets.

Home Assistant renders field help as markdown, which means HTML. The browser
reads `<hp>` as an unknown tag and the sanitizer drops it, so the field showed
`sensor._target_temperature_water` — an example that helps nobody.

These were the only three placeholders of that shape in the shipped texts, all
three introduced by v3.48.0. They are now spelled out, and the text names both
entities rather than one:

> Stiebel ISG example: `sensor.heatpump_target_temperature_water` (hot water)
> or `sensor.heatpump_target_temperature_hk_1` (heating circuit) — the prefix
> is your own device's name.

A test now rejects angle-bracket placeholders in every shipped UI string, so
this cannot come back quietly.

## Upgrading

Text only — nothing changed in behaviour, schema or the backend contract. No
re-provisioning; the corrected help text appears the next time you edit a
device.
