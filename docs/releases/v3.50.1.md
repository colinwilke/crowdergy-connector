# v3.50.1 — device profiles now apply to every device type

Fixes device profiles (crowd presets) being skipped or only partly applied
when adding a device.

## Fixed

- **Heating, warm water and air conditioning now offer device profiles.**
  These types went straight from the configuration-mode question to the
  entity step and never reached the profile picker. The picker now comes
  first for every profile-capable type. A chosen profile sets the
  configuration mode from its control entity (climate / water_heater entity
  → climate mode with the field pre-filled, otherwise manual). Without a
  profile, the configuration-mode question follows as before.
- **Control values come from the profile.** The "on"/"off" values, the
  cooling value and the repeat-command mode are now pre-filled from the
  profile instead of left empty.
- **"Invert power sign" from a profile is applied** and read correctly as
  true/false.

As before, everything is only pre-filled and confirmed by the user; control
entities are never guessed.

## Upgrading

No backend change needed. No entry-data change, no re-provisioning. Existing
devices are unaffected; the fix applies when adding a device.
