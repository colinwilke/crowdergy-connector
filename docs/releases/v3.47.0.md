# v3.47.0 — a dead inverter now reads as "no data", not as 0 kW

When the source behind Home Assistant goes away — the inverter drops off
Modbus, the vendor cloud is down, the integration is reloading — its
entities go `unavailable` while HA itself stays perfectly healthy. The
connector kept its heartbeat, so Crowdergy still saw a live connection,
and every reader in the tick returned `None`.

Until this release the payload turned that `None` into a number:

```
{"power_kw": 0.0, "is_online": true}
```

An invented measurement. The backend could not tell it apart from a real
zero, so the app showed green tiles at 0 kW — which reads as "the plant
is dead" or "Crowdergy is broken", not as "no data". The 0 kW rows also
went into the history for good: day chart, self-sufficiency, the PV peak
estimate and the RLS fit all counted them.

## Changed

- **`is_online` now tells the truth.** If a device has measurement
  entities mapped and **none** of them carries a value, the PATCH
  reports `is_online: false`.
- **`power_kw` is omitted instead of zeroed** in that case. This is the
  half that matters server-side: the backend's history aggregates all
  filter on `power_kw IS NOT NULL`, so an omitted reading is skipped
  everywhere a fabricated `0.0` would have been summed.
- **The HA sensors of this integration follow suit** — they show `None`
  rather than a made-up zero while the source is gone.
- **A change of `is_online` always sends a row.** It joined the
  categorical fields in the send-decision gate, so recovery is visible
  immediately even when the returning power reading happens to be 0 kW
  (solar at night).

## How the decision is made

All-or-nothing, deliberately. `is_online: false` requires that **every**
mapped measurement slot is dead — power, second power, SoC, vehicle
status, current temperature, both energy counters, and the solver/chart
extras. One flaky sensor next to four healthy ones is not a data outage,
and a false alarm costs more trust here than a missed partial fault. The
failure this targets takes all entities of one integration down at once.

Control slots (`entity_control`, `entity_charge_mode`,
`entity_cool_control`) are **not** part of the decision: a switch in HA
stays available while the inverter behind it is gone. They keep being
reported as before, so manual on/off still propagates during an outage.

A device with **no** measurement slot mapped is unchanged — that is a
configuration, not a fault, and it keeps reporting `is_online: true`.

## Notes

- Requires no re-provisioning and no config change.
- Backwards compatible: older backends simply store the `is_online`
  flag they already accept.
- The matching backend release surfaces this as a per-device state in
  `GET /me/health` ("Jetzt aktiv" in the app), naming each affected
  device — and it stops the solver from planning on invented values
  (a battery without a live SoC leaves the optimisation and falls back
  to the inverter's own control).
