# v3.36.0 — Uniform "controllable" capability flag

No breaking changes. No HA-version bump, no new entity/preset schema slots →
no new Box-vendor matrix row. After updating, re-provision (or edit) each
device once so the new flag is sent to the backend.

## Changed

- **New connector-computed boolean `control_entities_mapped`** sent for all
  controllable device types, so the backend and the iOS app can render
  "controllable" vs "read-only" uniformly instead of guessing per type
  (`charge_mode_value_*` for wallboxes, dormant `battery_value_*` for
  batteries, `control_status` for thermal devices).
- The flag is derived from the presence of the control entity each type's
  `_apply_*` guard actually needs:
  - **wallbox** — `entity_charge_mode`
  - **battery** — `entity_battery_mode` **plus** active/passive values; the
    power setpoint alone is not enough (`_apply_battery_setpoint` skips
    without a mode select)
  - **heating / warm water / generic** — `entity_control`
  - **air conditioner** — `entity_control` or `entity_cool_control`
- Only the derived boolean crosses to the backend; entity IDs stay
  connector-local (already persisted via `_build_device_record`).

## Why

A fully controllable battery (mode + setpoint mapped) showed up permanently
as "read-only" in the app, because those entities stay connector-local and
the app was looking at the never-populated `battery_value_*` fields. This
flag is the one honest channel for real controllability.

## Notes for existing installs

The backend column already exists. Update the connector, then open each
controllable device once via Configure → edit (or re-provision the box) so
the flag is populated.
