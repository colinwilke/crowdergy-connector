# v3.51.0 — heating via the room setpoint, no more false manual-override alerts

## Changed

- **Space heating is controlled via the room setpoint, never the flow
  temperature.** The heat pump keeps running its own heating curve.
  While heating, Crowdergy writes the room setpoint the cloud asks for
  (to the control entity and, if mapped, the ECO setpoint); when not
  heating it writes your "Off" value. When heating is cheap or
  efficient right now, the setpoint is raised further.
- **The "flow setpoint" mapping slot is gone.** An existing mapping is
  ignored; shared device profiles that still contain it drop it.
- **Daily write budget for heat-pump setpoints:** at most 24 writes per
  setpoint entity and day (heating/hot water), to spare the heat pump's
  controller memory. When it is used up, the last value stays and the
  device reports the write protection until midnight.

## Fixed

- **No more "manual operation detected" for Crowdergy's own values.**
  A setpoint that still shows Crowdergy's previous value, or the value
  from just before its last write (slow integrations, e.g. after a Home
  Assistant restart), is re-written instead of pausing control for 2 h.
  A value Crowdergy never wrote still pauses control as before.

## Upgrading

Requires the backend version deployed 2026-10-24 (late evening) that
sends the room setpoint. Check the "Off" value of your heating: it
should be low (e.g. 10 °C). No entry-data change, no re-provisioning.
