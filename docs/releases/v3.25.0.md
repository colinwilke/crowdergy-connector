## v3.25.0 — Branch-Konsolidierung (v3.21.2–v3.21.4 + v3.23.0)

Konsolidierungs-Release. Die in einem parallelen Branch
(`claude/trusting-planck-4f9txj`) entstandenen Releases v3.21.2 →
v3.21.4 waren bisher per HACS-Tag live, aber nicht auf `main`. Sie
sind jetzt cherry-picked und mit allen v3.22.0/v3.23.0-Review-Fixes
in **einer** Quelle vereint. Inhaltlich neu sind keine Features,
aber `main` ist jetzt der Single-Truth-Stand für alle aktiven
Connector-Pfade.

### Enthalten zusätzlich zu v3.23.0

- **v3.21.2 — KOSTAL-Preset Schema-Erweiterung:** Crowd-Contribution-
  Pipeline sendet `integration_domain` mit (siehe
  `entity_mapper.dominant_integration_domain`). Backend kann
  Presets jetzt der HA-Integration zuordnen aus der sie stammen,
  Voraussetzung für Box-Phase-6-Wizard-Pickern.
- **v3.21.3 — E2E-Konsistenz Bezug/Entladen ↔ Einspeisung/Laden:**
  Coordinator (`_apply_*` + Frame-Dispatch) und User-facing Strings
  durchgehend device-relativ. `entity_energy_total` = Bezug/Entladen-
  Zähler (device → home), `entity_energy_discharged_total` =
  Einspeisung/Laden-Zähler. Strings + DE/EN-Translations entsprechend
  beschriftet.
- **v3.21.4 — Explizite in/out-Deltas:** Telemetry-Patches schicken
  jetzt zwei UNSIGNED Felder `energy_kwh_in_delta` (Bezug/Entladen)
  und `energy_kwh_out_delta` (Einspeisung/Laden) statt eines signed
  Wertes. Backend leitet `energy_kwh_delta = in − out` ab. Vorzeichen-
  Math an genau einem Punkt, kein Reverse-Engineering der Magnitude.

### Kompatibilität

Vollständig backward-kompatibel: das Backend akzeptiert weiterhin
das alte signed `energy_kwh_delta`-Feld für Pre-v3.21.4-Connector-
Installationen. HACS-Update auf v3.25.0 ist drop-in, kein User-
Eingriff nötig.

### Hinweis

Tag v3.24.0 wurde von einer parallelen Box-Memory-Docs-Session auf
origin belegt — daher der direkte Sprung auf v3.25.0.
