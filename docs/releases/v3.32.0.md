## v3.32.0

### Feature — Crowd-Presets für Heizung / Warmwasser / Klima (#68)

Das Crowd-Preset-Slot-Schema (`preset_spec.PRESET_SLOT_SPEC`) deckte bisher
nur solar / grid / battery / wallbox ab — für die steuerbaren thermischen
Lasten erzeugte der „Share setup"-Beitrag leere Maps, es konnten also keine
Presets für sie entstehen.

Neu sind **heating**, **warmwater** und **aircon** preset-fähig:

- Pflicht-Slots: `entity_current_power_kw` + `entity_control` (analog zur
  Wallbox = Leistung + Lademodus).
- Optional: `value_on` / `value_off` (Steuerwerte — bei binären
  Steuer-Entities wie `switch`/`input_boolean` leer lassen, der Connector
  schaltet implizit per `turn_on`/`turn_off`; nur `select`/`climate`/
  `water_heater` brauchen die Strings), `entity_current_temp_c`,
  `entity_energy_total`, `invert_power_sign`.
- heating/aircon zusätzlich: `entity_cool_control`, `value_cool_on` /
  `value_cool_off` (Kühl-Seite; `supports_cooling` leitet das Backend ab).
- heating zusätzlich: `entity_vorlauf_setpoint_c` / `entity_vorlauf_temp_c`
  (modulierende Wärmepumpen).

Der Contribute-Flow ist spec-getrieben (`PRESET_CAPABLE_TYPES`) und öffnet
sich automatisch für die neuen Typen. Anonymisierung bleibt gewahrt: nur
spezifizierte Slots verlassen die Installation; installationsspezifische
Felder (z.B. `shares_hardware_with_device_id`) sind bewusst nicht im Preset.

Additiv, keine Re-Provisionierung nötig.
