## v3.26.0 — Crowd-Preset-Store: v3.24.0-Konsolidierung + verbindlicher Vertrag

Konsolidierungs- und Vertrags-Release. Die v3.25.0-Konsolidierung
hatte das getaggte v3.24.0 (Mapping-Dictionary + Contribute v0.2,
Branch `claude/beautiful-thompson-0a2wvl`) NICHT enthalten — `main`
war damit hinter einem bereits veröffentlichten HACS-Release. Dieses
Release führt beide Stränge zusammen; parallel ist die Backend-Seite
des Stores (Staging/Promotion/Kuration, Backlog #9) umgesetzt.

### Enthalten (aus v3.24.0)

- **`preset_spec.py` (SSOT, public Teil des Vertrags):**
  `PRESET_SLOT_SPEC` je Device-Type (solar/grid/battery/wallbox;
  Slot-Arten entity/value/flag + `required`), `PRESET_VALUE_SLOTS`,
  `extract_preset_maps()` (Allowlist = Anonymisierung),
  `missing_required_labels()` (Vollständigkeits-Gate).
- **Contribute für alle vier preset-fähigen Typen** (vorher
  solar-only) inkl. `value_map` (Select-Optionen/Flags, Flags als
  `"true"`); Preset-Picker in beiden Add-Flows, value_map füllt die
  Werte-Steps vor, Staging-Badge „Community, noch unbestätigt".
- **`box_add_device` prüft nach Slot-Art:** Entity-Slots gegen
  `MAPPABLE_ENTITY_DOMAINS`, Value-/Flag-Slots gegen
  `PRESET_VALUE_SLOTS` (Punkt im Wert ok), unbekannte Keys
  Default-DENY.

### Neu in v3.26.0

- **`docs/crowd-preset-store.md` ist jetzt der verbindliche,
  konsolidierte Vertrag** — inklusive der implementierten
  Backend-Realität: Staging (`staged`/`approved`), Promotion ab
  `CROWD_PRESET_THRESHOLD` (Default 3) UNTERSCHIEDLICHEN Usern,
  eingefrorenes Mapping ab approved, Kurations-API
  (`/crowd-presets/curation/*`), Lookup mit `status`/`value_map`/
  `updated_at`. Der Admin-Ausbau bleibt als Stufe-2-Design im Doc.
- `value_map` wird nur gesendet, wenn es belegt ist (Beiträge bleiben
  gegen Alt-Backends gültig).

### Kompatibilität

- Keine Breaking Changes für normale HACS-Installationen.
- Deploy-Reihenfolge: Backend (Migration `20260612_0001`) vor diesem
  Release ausrollen.
- Box: Battery-/Wallbox-Presets brauchen Vendor-Pin ≥ v3.24.0
  (aktueller Pin v3.25.0 erfüllt das NICHT für die
  box_add_device-Value-Slot-Prüfung — Pin nach diesem Release auf
  v3.26.0 bumpen).
