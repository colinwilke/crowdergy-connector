# v3.50.5 — no false "manual operation detected" on modulating heating

## Fixed

- **Heating with a flow-temperature setpoint on the same climate entity
  no longer reports manual operation by itself.** When on/off runs as
  max/min target temperature and the flow-temperature setpoint goes to
  the same entity, the hold loop compared against max/min, overwrote the
  flow setpoint or mistook Crowdergy's own write for a manual change and
  paused control for 2 hours. The flow setpoint is now the commanded
  value for that entity (hold, override detection, ECO mirror, control
  effect check). A real manual change is still detected.
- An on/off switch that arrives together with a new flow setpoint is now
  a single write instead of two opposing ones.

## Upgrading

No backend change required, no entry-data change, no re-provisioning.
