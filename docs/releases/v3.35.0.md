# v3.35.0 — Heat pumps controlled via min/max target temperatures only

No breaking changes, no re-provisioning needed. No HA-version bump, no new
entity/preset schema slots → no new Box-vendor matrix row. Existing
mode-string mappings ("heat"/"off") keep working unchanged.

## Changed

- **Heat pumps (heating / warm water) are never hard-switched anymore.**
  When the control entity is a `climate.*` / `water_heater.*` entity and the
  mapped on/off values are temperatures, Crowdergy only moves the target
  temperature between the mapped **maximum (On)** and **minimum (Off)** via
  `set_temperature` — there is no `set_hvac_mode("off")` /
  `set_operation_mode("off")` in this mode; the heat pump itself decides how
  long its compressor runs. This generalises the established warm-water
  pattern (`number` setpoint entities via `set_value`, unchanged).
- **Idempotency, hold loop and resync are target-temperature aware:** in
  temperature mode they compare the entity's `temperature` attribute instead
  of its state, so there are no redundant re-writes; the on/off read-back
  maps max-temp → on, min-temp → off, any other setpoint → unchanged.
- **Config flow:** heating/warm-water devices with a climate/water_heater
  control entity now get °C number fields (range from the entity's
  `min_temp`/`max_temp`) instead of an HVAC-mode dropdown on the
  switching-value pages. Air conditioners stay mode-based.
- **Prominent disclaimer** added to the README (German + English) and to the
  pairing/value-mapping setup pages: Crowdergy controls real devices — verify
  your mappings and temperature limits; use at your own risk.

## Notes for existing heat-pump mappings

Open the device once via Configure → edit and enter your minimum ("Off") and
maximum ("On") target temperatures on the switching-values page. Numeric
values switch the device to temperature mode automatically.
