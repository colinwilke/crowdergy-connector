# v3.54.2 — charge-mode hold backs off when the device does not answer

## Fixed

- **No more write storm against an unreachable device.** When the entity
  behind a wallbox or battery charge mode failed every write (for example
  because the device's API timed out), Crowdergy kept re-writing the mode
  every 15 seconds and logged a full traceback each time. The interval
  now doubles with every failed write, up to 5 minutes, and returns to
  15 seconds after the first write that succeeds. A new command from
  Crowdergy is still written immediately.
- **Quieter log during an outage.** Only the first failure of a series is
  logged as an error with traceback. Later failures are a one-line
  warning with a counter, and the recovery is reported once.

## Upgrading

No backend update required, no entry-data change.
