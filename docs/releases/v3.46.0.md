# v3.46.0 — Sicherheitsbündel: Write-Clamp, Schreib-Circuit-Breaker, manuelle Übersteuerung

Drei Hardware-Schutz-Features (SSOT-Backlog #135/#136/#140; Backend-Hälfte
ist seit backend#154 auf Prod — **dieses Release setzt das deployte Backend
voraus**, sonst 422en die neuen Telemetrie-Flags die Payload).

## Write-Clamp gegen die Entity-Grenzen (#135)

Jeder numerische Schreibvorgang wird gegen die Grenzen der Ziel-Entity
geklemmt (climate/water_heater `min_temp`/`max_temp`, number/input_number
`min`/`max`) — an allen Write-Sites: Entity-Control (number + WP-Temperatur-
Modus), Vorlauf-Setpoint, Batterie-Setpoint, Wallbox-Ladestrom. Ein Clamp
loggt WARNING (immer ein Mapping-/Grenzen-Fehler, nie Normalfall).

## Schreib-Circuit-Breaker pro Entity (#136)

Harter Zähler je (Entity, Stunde): über `WRITE_BREAKER_MAX_PER_HOUR` (500)
wird für dieses Gerät bis zum Fenster-Rollover nichts mehr geschrieben und
`write_breaker=True` geht als Telemetrie-Flag ans Backend (→ Meldung
„Jetzt aktiv" in der App). Fängt jede künftige Write-Storm-Regression,
unabhängig davon, wo der Bug sitzt.

## Manuelle Übersteuerung erkennen und respektieren (#140)

Der AUTO-Hold behandelt Drift, der nicht von einem eigenen Write der
letzten 30 s stammt, als Nutzer-Eingriff: das Gerät wird 2 h pausiert,
der Hold beendet, `local_override=True` gemeldet („Manuelle Bedienung
erkannt — Crowdergy pausiert dieses Gerät"). Danach übernimmt der
nächste MPC-Tick automatisch. Nur im AUTO-Modus scharf — der
ALWAYS-Modus (Auto-Reset-Register) bleibt unverändert.

## Sonstiges

- Telemetrie sendet `write_breaker`/`local_override` für alle steuerbaren
  Typen (auch False — das Backend cleart daraus die Zustands-Uhren).
- Kein Schema-/Entity-Slot-Change, kein Re-Provisionieren nötig.
- Tests: +15 `test_safety_bundle.py`; Full-Suite 277 grün.
