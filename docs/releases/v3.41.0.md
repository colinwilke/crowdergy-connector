# v3.41.0 — Share device profiles that use Home Assistant helpers

Some device profiles map a control slot to a Home Assistant **helper** the
contributor created themselves (an `input_select`/`input_number`/
`input_boolean`, e.g. an `input_select` that drives a Modbus automation for
a battery). A user receiving that profile doesn't have the helper, so the
slot never resolves. This release makes such helpers shareable.

No schema/telemetry/dispatch change; additive and backward-compatible.

## Added

- **`required_helpers` on shared profiles.** When you share a device setup,
  the connector now inspects each slot mapped to an `input_select`/
  `input_number`/`input_boolean` helper and attaches a structured spec
  (options / min / max / step / unit / name) read from your live Home
  Assistant config, so a receiving install can rebuild the helper. Native
  `select`/`number` entities are not helpers and are never included.
- **Profile picker tells you when a profile needs helpers.** A profile that
  requires helpers is labelled `· HA-Helfer nötig: …`, and the helper slot
  IDs are pre-filled as suggestions in the entity step.

## Notes

The connector runs inside Home Assistant and cannot reliably create
`input_*` helpers itself, so it **informs** you which helpers a profile
needs — create them once under Settings → Devices & Services → Helpers,
then confirm. (The Crowdergy Box, which drives Home Assistant over
WebSocket, provisions them automatically during setup.)

`required_helpers` provisions only the helper itself, not the hardware
bridge behind it (a Modbus automation, register map, host/slave) — that is
installation-specific and belongs in a curated vendor package.
