# v3.50.3 — no writes for devices with Crowdergy AI switched off

## Fixed

- **A device with Crowdergy AI switched off is no longer written to.**
  The charge-mode hold kept re-writing the last held mode every 15 s even
  after the AI was switched off. A second config entry with the AI off that
  mapped the same entity could therefore keep overriding the wallbox mode
  set by the first entry. Now, for a device with the AI off:
  - only commands marked as manual (`origin: "user"`, e.g. a mode change
    from the app) are executed — once, without a hold;
  - all other commands are ignored;
  - a running hold stops, and the lease fallback no longer writes a safe
    default.

Switching the AI off still applies its one-time hand-over (battery to
passive, heating/hot water off) as before.

## Upgrading

Requires the matching backend version (deployed 2026-10-08) — older
backends do not mark manual commands, so manual mode changes from the app
would be ignored while the AI is off. No entry-data change, no
re-provisioning.
