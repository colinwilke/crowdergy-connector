## v3.33.3 — Coordinator per-tick state prefetch (#56)

Internal performance optimisation — no user-facing behaviour change, no
config-flow or onboarding change, no re-provisioning needed.

### Changed

- **Per-tick HA-state prefetch (#56):** the per-device telemetry tick used
  to call `hass.states.get` once per *reader reference* — so an entity
  mapped to more than one slot (e.g. a climate entity feeding both the
  `is_on` and the `cool_on` derivation, or a sensor read by both
  `current_temp` and an extra field) was fetched 2–3× each tick. All
  `_read_*` helpers now route through `_get_state`, which prefers a
  per-device snapshot collected once at the start of that device's
  synchronous read phase (`_prefetch_device_states` → `_state_cache`) and
  cleared before the first `await`. A shared entity is read once; hold
  loops and the command dispatcher keep reading live state (no
  cross-coroutine staleness).

No HA-version bump, no new entity/preset slots → no new compatibility-matrix
row for the Box vendor pin.
